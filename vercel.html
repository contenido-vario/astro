Desplegar en Vercel

1. Ejecutar el comando


pnpm astro add vercel

Esto actualizará automáticamente tu archivo astro.config.mjs configurando el adaptador:

astro.config.mjs

2. Subir el código a GitHub, GitLab o Bitbucket (otros repositorios)

Asegúrate de NO SUBIR las credenciales de Supabase o las claves de Stripe o Brevo (archivo .env). Debes subir todo el código fuente de tu proyecto, excluyendo los archivos generados automáticamente y los datos sensibles.

A continuación tienes el desglose exacto de lo que SÍ debes subir y lo que NO debes subir.

Lo que sí debes subir:
  1. src/ (Toda la carpeta): Contiene tus componentes, páginas, estilos, scripts y la lógica de integración.
  2. public/ (Toda la carpeta): Archivos estáticos públicos como el favicon, imágenes estáticas, robots.txt, etc.
  3. astro.config.mjs (o .ts): El archivo de configuración de Astro (donde está configurado el adaptador de Vercel).
  4. package.json y package-lock.json (o pnpm-lock.yaml / yarn.lock): Definen las dependencias de tu proyecto (incluyendo @astrojs/vercel y @supabase/supabase-js) para que Vercel sepa qué instalar.
  5. tsconfig.json: Configuración de TypeScript de Astro.
  6. .gitignore: El archivo que le indica a Git qué cosas debe ignorar (muy importante).
  7. README.md (opcional): Documentación básica del proyecto.
Lo que no debes subir:

Estos archivos y carpetas nunca deben llegar al repositorio:

  1. node_modules/: Se genera al instalar dependencias. Vercel ejecutará pnpm install automáticamente al desplegar.
  2. .astro/: Archivos temporales de caché de Astro.
  3. dist/: Carpeta donde se genera la compilación final. Vercel la creará durante el despliegue.
  4. .env / .env.local: Contiene tus claves secretas de Supabase. Nunca lo subas.

3. Importar el proyecto en Vercel y configurar las variables de entorno

  1. Inicia sesión en Vercel y haz clic en Add New > Project.
  2. Selecciona tu repositorio de Git.
  3. Vercel detectará automáticamente que el framework es Astro.
  4. En la sección Environment Variables añade las claves
  5. Haz clic en Deploy.

Aquí tienes la lista completa de variables en Settings → Environment Variables:

VARIABLEVALOR
PUBLIC_SUPABASE_URLTu URL de Supabase
PUBLIC_SUPABASE_ANON_KEYTu anon key
SUPABASE_SERVICE_ROLE_KEYTu service role key
STRIPE_SECRET_KEYsk_live_... o sk_test_...
STRIPE_WEBHOOK_SECRETwhsec_...
BREVO_API_KEYTu API key de Brevo

Todas deberían estar en tu .env local. Es el mismo conjunto de variables que luego replicas en Vercel para producción

Marca las variables como Secret (write-only) en Vercel para que nadie en tu equipo pueda leer el valor una vez guardado.
